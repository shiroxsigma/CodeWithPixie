# Chatを入口にした共通エンジン構成

2026-09-29

## 使い方

`setup.bat` で依存を導入し、`run.bat` で起動する。最初は会話画面が開く。
「編集」でエディタへ移動し、「会話」で戻る。表示切替ではセッションを作り直さない。
会話、生成中のストリーム、入力途中の文章、未保存バッファを同じ画面内で保持する。
ブラウザの再読込をまたぐ自動セッション復帰は今回の変更には含めない。
保存済みの会話は「会話」一覧から復元できる。

ファイルは会話画面の「ファイルを探す」から検索・選択できる。選択したファイル、
変更案の差分、実行計画を確認するときは編集画面が開く。背景のファイル再読込だけでは
画面を移動しない。Code / Note / Planは従来どおり作業モードとして独立している。

狭い画面では編集領域を全幅で表示し、差分承認中は判断ボタンと停止ボタンも表示する。
ファイルパネルはEscまたは外側クリックで閉じ、依頼例は入力中の文章を上書きしない。

## エンジンと配布

エンジンの実装はAWPの `pixie_core` に集約し、CWPの依存ファイルでAWPの版を固定する。
今回の配布は `anythingpixie 0.2.0`、AWPコミット `5c904da` を指定した。
コアはCLIモジュールを読み込まずに動作する独立パッケージになった。AWPのCLIは既存の
起動方法と互換モジュールを維持している。WebとCLIのリポジトリは維持し、配布単位を
分けたまま共通実装を利用する。

通常導入にはAWPの隣接チェックアウトが不要。`awp_src` が空ならインストール済みコアを
優先する。開発用ソースを使う場合だけ明示する。未導入の開発環境には兄弟ディレクトリの
フォールバックも残す。CIは隣接AWPをチェックアウトせず、配布パッケージを検証する。

## 検証

- CWP Python全体: 371件成功。開発用ソースとインストール済みコアの両経路で実行。
- Web単体: 11件成功。型検査、ビルド、Prettierの検査も成功。
- ブラウザ29件成功: 会話中の表示切替、未保存編集の保持、停止、承認、保存競合、履歴復元、
  スマホ幅のファイルパネルと差分承認を検証。試験用ポートと作業フォルダを使用する。
- AWP: 全体テストに加え、コアだけをコピーした隔離プロセスで起動・読み書き・CLI非依存・
  インストール先にデータを生成しないことを検証。wheelを新規venvへ導入する試験も実施。
  Windowsでripgrepがない場合の代替検索も、対象範囲・結果上限・中断とともに検証した。
- 実モデル: LM Studioで稼働しているQwen3-VL 4Bモデルへ、CWPの `/api/chat` と
  インストール済みコアを通して送信。日本語のストリーム応答と `completed` を8.61秒で確認。
  この試験は単純な会話の疎通確認であり、任意のコード生成品質を保証するものではない。

実モデル試験は隔離した作業フォルダとプロセス内設定を使用した。通常設定のBonsai用
エンドポイント `127.0.0.1:8098` は検証時に接続できず、保存済みのモデル選択は変更していない。
利用時はBonsaiサーバーを起動するか、設定から稼働中のサーバーを選ぶ。

Computer Useは画面取得を実施したが、確認用ブラウザの起動は自動承認レビューで
「ポリシーでブロック」と拒否された。操作検証はPlaywrightで行い、デスクトップ幅と
スマホ幅の画面画像も確認した。Computer Useによる一連の操作が成功したとは扱わない。

ローカルの画面画像と実モデルの記録は `logs/` に保存し、Git管理には含めない。
