# 実モデルによる作成・編集の継続検証

実施日: 2026-09-21。Bonsai 2 27B の実サーバー `127.0.0.1:8098` に接続し、
CWP のチャット・承認 API を通して、異なる小規模プロジェクトを作成してから編集する。
ファイル生成後の手直し、モデルへの追加ヒント、外部からのテスト実行の代行は行わない。

## 再実行

現在選択中のモデルを使用する。CWP の仮想環境に pytest が必要。

```powershell
.venv/Scripts/python.exe scripts/evaluate_cwp.py --cases 3
```

試験専用の CWP をポート8782で起動し、終了時に停止する。ポートが使用中なら開始せず、
`--port` で別ポートを指定できる。CWP と共通エンジンのソース・設定を実行時にコピーし、
試験中のソース変更から分離する。起動中の通常版CWPの設定・作業フォルダは変更しない。

結果は `logs/model-eval-日時/` に残る。`results.json` に各段階の成否、
`manifest.json` にソースhash・モデル・予算、`*-prompt.txt` に入力、
`*.jsonl` にCWPの生イベント、`receipts/` に実pytestの記録を保存する。
`artifacts/課題/段階/` は各段階の生成ソースで、後続編集前の状態も保持する。
これらのローカル記録はGit管理対象外。全段階合格のみ終了コード0、それ以外は1。

## 課題と合格条件

| 課題 | 作成 | 続く編集 |
|---|---|---|
| 数値集計 | 件数と合計、空入力と入力不変性 | 平均を追加、空入力ではNone |
| 文字列整形 | 空白の統一、文字の大小を保持 | casefoldオプション、既定動作を維持 |
| タグ整理 | 空要素と重複を除去、順序を維持 | casefoldで重複判定、最初の表記を保持 |

各課題で実装とpytestファイルだけの編集を許可し、実行コマンドも指定したpytestに限定する。
作成・編集は同じCWPセッションで行い、課題間では作業フォルダとセッションを分離する。
作成が不合格の場合、その課題の編集は未実施として全体を不合格にする。

合格には、次のすべてが必要。

1. CWPが正常終了し、コアの終了理由も最終回答の正常経路である。
2. モデル自身が、最終編集後のソースでpytestを実行して成功する。
3. 作業フォルダ外に置いた独立チェックでも仕様を満たす。
4. 許可した範囲を外れる承認要求がない。
5. 実装・テストの2ファイルがそれぞれ60行未満である。

pytest観測プラグインはテストの開始・終了、終了コード、実行件数、開始・終了時の
ソースhashを作業フォルダ外へ記録する。最新試験の成功と最終ソースの一致を必須とし、
古い成功、試験後の編集、途中終了、0件・全スキップを成功に数えない。
観測記録と独立チェックは評価専用で、製品側の完了判定には注入しない。

## 今回見つかった問題

- Codeモードの既定ツール集合に `run_command` がなく、実装・テストファイルの作成後も
  テストを実行できなかった。CWPでCode用の23ツールを明示し、計画解除時にも復元する。
  Copilotの切替でも集合を保持し、計画中はコマンドを提示しない。
- コアの `turn_completed` イベントをタスク成功と混同し、一部の異常終了が
  `completed` のままになっていた。正常な終了理由だけを成功とし、上限到達・代替回答・
  不明な終了理由を区別する。
- 小規模編集でも長い仮説比較と行数の手計算を続け、テスト後の整形で時間切れになった。
  CWPのCode指示に、必要確認後の編集、形式制約の実測、最終変更後のテストを明示する。
- 評価用サンプルのpytestファイルが本体のテスト収集へ混入した。本体の対象を`tests/`に
  固定し、評価用プロジェクトには独立したpytest設定を置く。

修正前の予備試験 `model-eval-20260921-082156` は、数値集計の作成で600.3秒の
時間切れ。外部チェックは成功したが、モデルによるテスト実行がなく、不合格とした。

修正後の本試験 `model-eval-20260921-100021` は、作成2件が合格し、残る3段階は
不合格だった。数値集計の編集は実装、モデルpytest、独立チェックに成功した後、
許可していない追加の `python -c` 実行を要求して `user_rejected` で終了した。
文字列整形の作成は、初回pytest失敗後にテストを修正したが、再実行前に600秒で
時間切れとなり、テストファイルも68行で制約を超えた。タグ整理の編集は実装、
モデルpytest、独立チェックに成功したが、最終回答の候補再生成中に600秒で
時間切れとなった。監査結果も同じ不合格判定で、異常終了や古いpytest成功を
合格へ昇格させていない。

| 課題・段階 | 結果 | 終了理由 | モデルpytest | 独立チェック |
|---|---:|---|---:|---:|
| 数値集計・作成 | 合格 | `final_answer` | 合格 | 合格 |
| 数値集計・編集 | 不合格 | `user_rejected` | 合格 | 合格 |
| 文字列整形・作成 | 不合格 | `turn_timeout` | 不合格 | 合格 |
| タグ整理・作成 | 合格 | `final_answer` | 合格 | 合格 |
| タグ整理・編集 | 不合格 | `turn_timeout` | 合格 | 合格 |

## 適用範囲

これは小規模PythonプロジェクトのAPI経路の検証で、UI全操作、大規模リポジトリ、
長時間稼働、異なるモデルでの信頼性までは示さない。試験の共通エンジンは隣接AWPの
作業ツリーをコピーしており、既存の未コミット変更を含む。正確な対象はmanifestの
ソースhashで識別する。隣接AWPの作業内容への編集・コミットは行わない。
