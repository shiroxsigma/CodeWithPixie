# CWP 実プロジェクト作成・編集レビュー

実施日: 2026-09-20。CWP `http://127.0.0.1:8771` と Bonsai 2
`http://127.0.0.1:8098` の実接続で検証。

## 検証対象

作業フォルダは `workspace/bonsai-taskboard`。外部依存のないタスク管理アプリを
CWP の `/api/chat` から作成し、続く会話で完了済みタスクの一括削除を追加する。
実行記録はローカルの `logs/taskboard-*.jsonl` に保存。
サンプルと実行ログは既存の Git 除外対象に置く。

## 見つかった問題と修正

1. **実生成で思考打切りを空応答と誤認**。
   作成開始前に再試行を消費し、説明へ脱線することを実接続で確認した。
   pixie_core で思考打切りを専用状態として扱い、元の操作を続ける。
   同一チャンクの回答・ツール呼び出しを保持し、ツール引数の受信中に思考時間で切らない。
   3回連続の思考打切りは未完了として終了する。
2. **サーバーの生成タイムアウトが上書きされる**。
   ContextPolicy の600秒がセッション作成時に180秒へ戻っていた。
   Code/Note とターン制御でサーバー値を保持し、思考設定を変えても縮めない。
3. **停止後に確定済み変更が表示されない**。
   SSEを中断すると最終 `files_changed` を受信できない。
   中断APIで終了状態を返し、終了確認後にファイル一覧と保存済みエディタを更新する。
   未保存バッファは保持する。
4. **フォルダ切替中に旧ファイルを保存できる**。
   手動保存の完了を待ち、切替中は保存を禁止してエディタを読み取り専用にする。
5. **ツール引数の生成中もThinking表示が続く**。
   初回ツールチャンクで生成フェーズを通知し、UIを「ツール呼び出しを生成中」へ切り替える。
6. **引数なしの一覧と作業場所が一致しない**。
   `list_directory()` がプロセス起動フォルダを列挙する一方、`get_cwd()` は
   セッションの作業フォルダを返していた。モデルがこの矛盾を繰り返し検討して
   編集を進められないことを実接続で確認した。
   一覧・検索・コードマップ・未使用コード検出・ファイル統計の5ツールで、
   承認前のパス補完とツール本体の相対パス解決をセッション基準に統一した。
7. **編集後の再読取りが連続ループと誤判定される**。
   CWPでChangeSetを適用してもコアの実行履歴に変更が記録されず、
   読取→編集→確認読取が読取→読取に見えていた。
   成功したChangeSetの変更マーカーを実行履歴に記録し、確認読取を妨げないようにする。

コード生成の思考上限は60秒から180秒へ変更。生成全体600秒、無通信120秒。
GPU設定は `-ngl 64 -fa on` を継続する。モデル側の思考トークン予算は
2,048から512へ変更し、起動スクリプトの `-ReasoningBudget` で変更可能にした。

## サンプルの結果

- 公開先（ローカル起動中）: `http://127.0.0.1:8781`。
- `index.html` はBonsaiによるCWPチャットの書込ツールと差分承認から作成。
- 初回60秒思考設定では208秒で中断。180秒設定の作成はHTMLを書き込んだが、
  README作成前に600秒のターン上限へ達した。完全自動の一括作成成功とは扱わない。
- 続くAI編集で一括削除ボタンのHTMLを部分適用。作業フォルダの不一致により
  モデルが迷ったため中断し、残りのJavaScript・削除アイコン・複数形を
  **CWPのMonacoエディタで編集・保存**、READMEもCWP画面から新規作成した。
- 保存後のファイルAPIとの全文一致と、画面リロード後のREADME復元を確認。
- フォルダ修正後の新しいAI会話で、一覧取得・README読取り・見出しの部分編集を
  差分承認経由で実行。保存された変更が指定した見出し1箇所だけであることを照合。
  編集成立後もモデルが確認を繰り返したため212秒で中断した。この経路で
  上記のChangeSet後の読取誤判定を発見。最終修正は回帰テストで検証する。
- 実ブラウザで12項目成功: 追加、完了、Active絞り込み、Done絞り込み、保存復元、
  削除、375px幅、ブラウザエラーなし、一括削除で未完了を保持、削除結果の保存、
  ボタン無効状態、残り件数の複数形。

画面記録: `logs/taskboard-final.png`、`logs/cwp-sample-saved.png`。
AIの複数工程の自動完遂率と速度には引き続き改善余地がある。

## 2026-09-21 の追加改善

既存修正を CWP `3bc887b`、共通エンジン `3e4768a` にコミットした後、
次の改善を実装した。

- 承認済みChangeSetの適用直後に `files_changed` を通知する。生成終了を待たずに
  新しいファイルと更新内容を表示し、ターン中の変更バッジを累積する。
- エディタに未保存の編集がある場合は保持する。生成途中の破棄確認で進行を妨げず、
  保存前に確認が必要な状態として表示する。却下・適用競合時は変更通知を出さない。
- 共通エンジン `6181cc2` で適用済み変更を構造化して編集検証へ渡す。
  実テストが成功した小規模編集は既存の完了経路へ進める。
  適用通知自体をテスト成功とは見なさず、失敗・追加編集・次ターンへの持越しを防ぐ。
  複数操作を単一編集に縮約して完了条件を満たすことも避ける。

検証: CWP Python 308件、ブラウザE2E 23件、共通エンジン関連144件が成功。
新しい統合テストでは実ファイルの変更とpytest子プロセスの成功・失敗を検証した。
この追加分では実モデルによる長時間の自動完遂率・速度の再計測は行っていない。
